# Computer Architecture, Memory, Interconnect, SoC Integration and AI Hardware: Standards Audit of TAPEOUT

Scope audited (read in full for factual claims): `src/lessons/arch.ts` (pipe, ooo, cache, coherence, dram, bus, noc, serdes, perf), `src/lessons/roles.ts` (sram L228-265, emu L402-425, npu L429-469), `src/lessons/frontier.ts` (soc-int L110-139, neuro L241-277), `src/practice/arch.ts` (all banks + 5 bosses), `src/practice/silicon.ts` (sramPractice, boss-memory, emuPractice, boss-fpga, plus HBM items in pkgPractice L471-499), `src/practice/domains.ts` (npuPractice, boss-ai), `src/practice/frontier-a.ts` (socintPractice/boss), `src/practice/frontier-b.ts` (neuroPractice/boss), labs `src/games/arch/levels-{pipe,cache,ooo}.ts` (briefs/hints), `src/games/spec/digital.ts` (fpga-map, fpga-fmax, ai-tile, ai-boss), `src/games/spec/memory.ts` (mem-snm, mem-assist), `src/glossary.ts`. Not audited: the OS scheduler/paging lab, which lives in `src/games/code/levels-os.ts` (outside the listed directories). No repo file was modified.

Severity scale: 5 = teaches something wrong that would hurt in an interview/job; 1 = cosmetic or pedantic. "DEFINITE" = contradicts a current standard; "OUTDATED" = was true for an earlier generation; "SIMPLIFICATION" = acceptable for teaching but worth a caveat; "GAP" = missing coverage.

Overall verdict: the architecture core (iron law, hazards/forwarding, load-use, 2-bit predictors, renaming/ROB, cache address split, AMAT, 3Cs, MESI/MOESI transitions, TSO store-buffer litmus, NoC hops/wormhole/bisection, credits, AXI handshake rule, AXI WRAP/4 KB rule, 8b/10b and 128b/130b efficiency, dual-Dirac jitter Q values, Amdahl, Little, roofline, geometric mean) is correct; I found no severity-4/5 errors. The problems are almost all **version drift** (HBM fixed at 1024 bits, DDR4-era refresh numbers, PCIe stops at Gen5/6, no CXL/UCIe versions), **pre-2021 AMBA terminology** (master/slave), **one DDR5 channel-definition slip**, an **MHA-only KV-cache formula applied to a GQA-shaped model**, a **legacy 18×18 FPGA DSP model**, and **coverage gaps** (FP8/MX/NVFP4, CHI/ACE/AHB/AXI-Stream, interrupt controllers, Rowhammer mitigations PRAC/RFM, PCIe 7/8, Ethernet/UALink/UEC).

## 1. Interconnect standards (AMBA, PCIe, CXL, UCIe, Ethernet, scale-up fabrics): current versions and correctness of the game's protocol facts

### Takeaway
The game's AXI facts (5 channels AW/W/B/AR/R, VALID must not depend on READY, READY may wait for VALID, transfer when both high, ID ordering, INCR/WRAP addressing, 4 KB boundary) and PCIe Gen1-5 math are correct, but it uses pre-2021 "master/slave" terminology, never names AHB/AXI-Stream/ACE/CHI, stops at PCIe 6 (PCIe 7.0 released June 2025, 8.0 at draft 0.5), gives no CXL/UCIe versions (CXL 4.0 at 128 GT/s since Nov 2025; UCIe 3.0 at 48/64 GT/s since Aug 2025), and has one imprecise flit-mode remark.

### Cited Findings
Current standards status (October 2026):
- AMBA AXI: Issue H.b (Jan 2021) "regularized terminology to use **Manager** to indicate the agent that initiates read and write requests and **Subordinate** to indicate the agent that responds"; master/slave appear only in older documents — [Arm AMBA AXI Protocol Specification](https://documentation-service.arm.com/static/63ff0ebd56ea36189d4e7ee7); [Scribd intro: "manager is synonymous with master in older documentation"](https://www.scribd.com/document/807470515/AMBA-AXI-introduction).
- Latest AMBA 5 releases: AXI Issue K (adds Memory Encryption Contexts, expanded MPAM, simplified MTE) and CHI Issue G (released March 2024, ninth public release; errata v4.0 Feb 2025) — [Arm community blog: updates to AXI and CHI](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/updates-to-amba-axi-and-chi-specifications); [Synopsys: first VIP for CHI-G](https://www.synopsys.com/blogs/chip-design/amba-chi-g-verification-ip.html); [Design&Reuse: AXI-K VIP](https://us.design-reuse.com/industryexpertblogs/54946/synopsys-amba-verification-ip-arm-axi-k-specification.html).
- PCIe 7.0 was released to members June 11, 2025: 128.0 GT/s raw, up to 512 GB/s bidirectional x16, same PAM4 + Flit Mode as PCIe 6.0 (64 GT/s) at 32 GHz Nyquist — [PCI-SIG PCIe 7.0 webinar Q&A](https://pcisig.com/blog/pcie-70-specification-next-generation-performance-meet-needs-advanced-ai-applications-webinar); [Rambus guide](https://www.rambus.com/blogs/the-ultimate-guide-to-pci-express/).
- PCIe 8.0: announced Aug 2025, Draft 0.5 available to members (May 2026), targeting 256.0 GT/s and 1.0 TB/s bidirectional x16, release planned by 2028 — [PCI-SIG: PCIe 8.0 Draft 0.5](https://pcisig.com/blog/pcier-80-specification-draft-05-now-available-track-2560-gts-transfer-speeds-2028); [PCI-SIG in the news](https://pcisig.com/newsroom/in-the-news).
- PCIe 6.0 Flit Mode: 256-byte flit = 236 B TLP + 6 B DLP + 8 B CRC + 6 B FEC; the per-TLP **LCRC is removed** in flit mode (flit-level CRC replaces it) and a lightweight single-byte-correcting FEC is added; NAK/replay (including selective NAK) is retained — [Synopsys: PCIe 6.0 FEC and CRC](https://www.synopsys.com/blogs/chip-design/pcie-6-verifaction-fec-crc.html); [Cadence: flit-mode challenges](https://community.cadence.com/cadence_blogs_8/b/fv/posts/unravelling-pcie-6-0-flit-mode-challenges).
- CXL 4.0 released Nov 18, 2025: link rate doubled from 64 to 128 GT/s (PCIe 7.0 PHY), bundled ports, enhanced memory RAS; CXL 3.x = 64 GT/s; 1.x/2.0 = 32 GT/s — [CXL Consortium homepage](https://computeexpresslink.org/); [Wikipedia: CXL](https://en.wikipedia.org/wiki/Compute_Express_Link); [CXL 4.0 webinar PDF](https://computeexpresslink.org/wp-content/uploads/2025/12/CXL_4.0-Webinar_December-2025_FINAL.pdf).
- UCIe 3.0 released Aug 2025: 48 and 64 GT/s for UCIe-S (standard package) and UCIe-A (advanced package), up from 32 GT/s in 1.x/2.0, plus runtime recalibration and manageability — [UCIe 3.0 press release](https://www.businesswire.com/news/home/20250805909613/en/UCIe-Consortium-Introduces-3.0-Specification-With-64-GTs-Performance-and-Enhanced-Manageability); [UCIe specifications page](https://www.uciexpress.org/specifications).
- IEEE P802.3dj (200G/lane; 200G, 400G, 800G and 1.6 Tb/s Ethernet): sent to SA ballot Feb 2026; initial SA ballot closed successfully 26 March 2026 with >75% approval; project timeline targets completion around July 2026 (final approval status as of October 2026 not confirmed) — [Wikipedia: Terabit Ethernet](https://en.wikipedia.org/wiki/Terabit_Ethernet); [IEEE 802 LMSC email](https://ieee802.org/email/stds-802-lmsc/msg00846.html).
- Ultra Ethernet Consortium Specification 1.0 released June 11, 2025; v1.0.2 January 28, 2026 — [UEC launch](https://ultraethernet.org/ultra-ethernet-consortium-uec-launches-specification-1-0-transforming-ethernet-for-ai-and-hpc-at-scale/); [UEC spec history](https://ultraethernet.org/specification-history/).
- UALink 1.0: 200G-per-lane scale-up for up to 1,024 accelerators per pod — [UALink specifications](https://ualinkconsortium.org/specification/).

- The 128b/130b PCIe question generator is fine to keep, but a learner taught "PCIe 6 adds PAM4" with no 7.0/8.0 will look dated by 2026; one extra generator row for Gen6/Gen7 (flit) would close this.
- NoC content (`arch.ts:231-268`, `practice/arch.ts:472-512`) matches standard Dally & Towles-style treatment (diameter 2(k-1), XY turn restriction, wormhole ≈ H·tr + L/b, torus bisection 2k links, VC/protocol-deadlock separation); I found no errors.

### Gaps
- I did not obtain the exact current AXI issue letter beyond "Issue K" or CHI beyond "Issue G" from Arm's own release table; a later issue could exist by Oct 2026.
- NVLink generation/bandwidth figures were not sourced (proprietary; NVIDIA pages not fetched).
- Final IEEE SA approval date of 802.3dj was not confirmed (only ballot success in March 2026).

## 2. Memory standards (DDR5, LPDDR5X/LPDDR6, GDDR7, HBM3E/HBM4, timing, refresh, Rowhammer): are the game's numbers current?

### Takeaway
The DRAM access-timing model (hit = CL, closed = tRCD + CL, conflict = tRP + tRCD + CL), FR-FCFS, open/close page, charge sharing and Poisson repair math are correct, but HBM is hard-coded as 1024 bits/stack in ~12 places even though JEDEC HBM4 (JESD270-4, April 2025) is 2048 bits at up to 8 Gb/s (2 TB/s/stack); refresh numbers are DDR4's (64 ms / 7.8 µs) while DDR5 is 32 ms / 3.9 µs; one bank calls a 64-bit DDR5 DIMM a "channel"; and Rowhammer mitigation stops at "refresh neighbours sooner and ECC" (no TRR/RFM/PRAC).

### Cited Findings
Current standards status:
- HBM4, JESD270-4 (April 2025): up to 8 Gb/s across a **2048-bit** interface, up to 2 TB/s per stack; revision JESD270-4A (v1.1) published Dec 2025 — [JEDEC HBM4 press release](https://www.jedec.org/news/pressreleases/jedec%C2%AE-and-industry-leaders-collaborate-release-jesd270-4-hbm4-standard-advancing); [JEDEC JESD270-4A page](https://www.jedec.org/standards-documents/docs/jesd270-4a).
- HBM3 (JESD238): 1024-bit, 6.4 Gb/s, 819 GB/s per stack; HBM3E (JESD238A): same 1024-bit, 16 channels, ~9.6 Gb/s, >1.2 TB/s per stack — [Siemens HBM3E/HBM4 guide](https://blogs.sw.siemens.com/semiconductor-packaging/2026/04/24/hbm3e-hbm4-ic-design-guide/); [JEDEC HBM3 press release](https://www.businesswire.com/news/home/20220127005320/en/JEDEC-Publishes-HBM3-Update-to-High-Bandwidth-Memory-HBM-Standard).
- LPDDR6, JESD209-6, published July 9, 2025 — [JEDEC LPDDR6 press release](https://www.jedec.org/news/pressreleases/jedec%C2%AE-releases-new-lpddr6-standard-enhance-mobile-and-ai-memory-performance); [JESD209-6](https://www.jedec.org/standards-documents/docs/jesd209-6).
- DDR5 refresh: retention window cut from 64 ms (DDR4) to **32 ms** up to 85 °C; tREFI = **3.9 µs** at ≤85 °C (DDR4: 7.8 µs); 16 ms window at 85-95 °C — [Wikipedia: DDR5](https://en.wikipedia.org/wiki/DDR5_SDRAM); [Intel EMIF DDR5 device parameters](https://intel.com/content/www/us/en/docs/programmable/772538/current/m-series-fpga-emif-memory-device-ip-71982.html).
- DDR5 DIMM organization: two independent 32-bit channels (40-bit with ECC) per module; module data width still 64 bits — [Wikipedia: DDR5](https://www.Wikipedia.org/wiki/DDR5); [Kingston DDR5 collateral](https://media.kingston.com/kingston/articles/MKF_954-DDR5-Collateral_us.pdf).
- JESD79-5C (2024) added **Per-Row Activation Counting (PRAC)** with an Alert Back-Off (ABO) mechanism for Rowhammer; it tracks activations at wordline granularity — [Counterpoint, DRAMSec'25](https://dramsec.ethz.ch/dramsec25-papers/counterpoint-dramsec25.pdf); [ACM ASPLOS'25: PRAC + ABO](https://dl.acm.org/doi/abs/10.1145/3669940.3707278); [TechPowerUp: JEDEC updates DDR5 for Rowhammer](https://www.techpowerup.com/forums/threads/jedec-updates-ddr5-specification-for-increased-security-against-rowhammer-attacks-new-ddr5-8800-reference-speed.321808/).

Audit of game claims:
- **[OUTDATED, sev 3]** HBM fixed at 1024 bits: `arch.ts:186` "HBM… with a **1024-bit** interface per stack"; `arch.ts:189-190` "An HBM stack has a 1024-bit interface at ${gbps} Gb/s" with gbps ∈ {3.2, 6.4, **8**}; `arch.ts:192` "A 1024-bit bus is impossible on a PCB"; `arch.ts:194` recap "HBM = 1024 bits × Gb/s ÷ 8 per stack"; `practice/silicon.ts:473` "each stack has a 1024-bit interface", `:474,:479,:484` (gbps ∈ {3.2, 6.4, 9.6}), `:498`; `roles.ts:330` "HBM uses a 1024-bit interface per stack"; `glossary.ts:110` "with a 1024-bit interface per stack". - **[OUTDATED, sev 2-3]** `roles.ts:250` "every row must be **refreshed** every 64 ms (32 ms when hot)" and recap `roles.ts:264` "refresh every 64 ms" — DDR4 (and earlier) values; DDR5 is 32 ms normal, 16 ms hot. ### Inferences
- Since NVIDIA/AMD 2026 accelerators are moving to HBM4, a learner who answers "HBM = 1024 bits" in a 2026 interview will be flagged as dated; this is the single most visible currency issue in the module (severity 3 because the bandwidth formula still transfers).
- The refresh items are correct for DDR4 and only need a generation label; the arithmetic skill is unaffected.

### Gaps
